# CLAUDE.md

Working instructions for this repo. Keep it short and specific — add a rule when a mistake
is worth not repeating, not in anticipation of one.

## What this project is

Structuring San Francisco Planning Commission meeting minutes (1998–present) into an
**item-level** dataset of discretionary land-use decisions — the empirical backbone for
studying the *market for housing regulation*. One row is one request heard by the
Commission. A **meeting-level** table sits above it (time, type, venue, roll call, staff),
joined on the hearing date.

`STRUCTURE.md` maps the repo; `output/README.md` maps the reports.

## Data lives on Dropbox, not in git

The corpus is at `~/Library/CloudStorage/Dropbox/mfhr_data`, resolved by
`code/commission_minutes_processing/paths.py` (override with `MFHR_DATA_ROOT`). Never commit
data files. `labels.db` and `date_gold.db` are local stores and are git-ignored.

## LaTeX memos

- **Always check whether tables need resizing to the text width.** After compiling, grep the
  `.log` for `Overfull \hbox ... in alignment` — that means a table is running past the
  margin. Fix with `\resizebox{\textwidth}{!}{% ... }` around the `tabular`, or by trimming
  `p{}` column widths (remember `\tabcolsep` adds ~12pt per column, so widths summing to
  1.0 will overflow).
- TeX is installed but **not on the PATH** in non-interactive shells. Use
  `export PATH="/Library/TeX/texbin:$PATH"` then `pdflatex`. Run it twice so references and
  the table of contents settle.
- Compile before claiming a memo is done, and check `grep -c Undefined <file>.log`.
- **Track only the `.tex`, its `.pdf`, and its `.bib`.** Every other TeX output is
  regenerable and git-ignored (see the LaTeX block in `.gitignore`). Note gitignore has no
  trailing comments — `*.nav  # beamer` is read as a literal pattern.
- Each `output/` subdirectory carries one standing `memo.tex`, kept up to date rather than
  superseded by a new file.

## Figures

- Charts are generated by a script in `code/`, written to `output/…`, and committed as PDF.
  Never hand-place numbers in a figure that a script could compute.
- Faint raw series behind a bold smoothed line is the house style for time series. Say what
  the smoothing window is, and prefer a window of calendar time over a fixed number of
  observations when the observation frequency varies.
- Draw gaps rather than interpolating across them: a line through a year the corpus barely
  covers shows a trend that does not exist. 2018 was that year until 2026-09-04, when it was
  refilled from the S3 packet prefix (2 documents to 42). `SPARSE_YEARS` in
  `plot_meeting_timeseries.py` is where such a year gets named; it is empty now, and the
  rule stands for the next one.

## Extraction work

- **Freeze and hash before a validation round.** Write the SHA of the extraction modules to
  a `FROZEN_ROUND*.json`, verify it before scoring, and do not touch a rule while labelling
  is in progress. An accuracy figure measured after tuning against the same data is not an
  accuracy figure.
- Report in-sample and out-of-sample separately, and say which is which.
- When the machine and a hand label disagree, **check the source before assuming the machine
  is wrong.** Several times the label was the error.
- Prefer leaving a field empty or ambiguous over guessing. A blank is a question; a
  confident wrong value is a silent error that propagates. (See the two Lees: assigning
  every unresolved case to one of them produced a fake 9%-vs-0.4% absence gap.)
- Deterministic rules first. No LLM is used anywhere in the date or meeting-level pipeline,
  and that is a feature — the same page extracts identically on every run.

## Style

- Match the surrounding code. Scripts carry the standard header block
  (`Purpose / Inputs / Outputs / Author / Created / Notes`).
- Comments explain *why*, especially where a rule looks arbitrary — most of the regexes in
  this pipeline encode a specific archive quirk, and the quirk is the useful part.
- Prefer editing an existing script over adding a parallel one.
